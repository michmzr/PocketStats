# Private Coolify statistics dashboard candidate

This candidate preserves the unchanged deployed JAR, existing Atlas `test`, version-2 shared-dashboard marker and exact five-route statistics-only proxy. It has not been deployed. Contabo remains active-authoritative; no source stop, Atlas clone/export, credential change, DNS or public route belongs to this slice.

`pocketstats-launch` is the reviewed host guard with one container adaptation: backend binds `0.0.0.0:18080` inside its dedicated network, with no published backend host port. It retains Java17 path `/usr/bin/java`, heap512MiB, production profile/context, exact marker metadata/fields and forced index-disable CLI/environment. It strips injected Spring JSON/Java options. The proxy alone publishes `127.0.0.1:18081`; all sync/auth/unmatched routes are denied. Existing writable Atlas identity means this is not database-enforced read-only access.

Required image variables are explicit and have no fallback. `runtime-images.env.example` records the verified target Docker amd64 runtime/proxy image IDs and official Nginx manifest provenance. `RUNTIME.Dockerfile` builds only Temurin17.0.20.1 and Python3.12.3 with exact launcher paths, no application JAR or credentials. The runtime was built and verified in the existing bounded local Podman VM; both runtime-only archives have since been loaded on the target and their platform, ordered layers and runtime metadata compared to the archives. Its Python package layer used the observed Ubuntu repositories and is fixed by the resulting image ID, not a reproducible repository snapshot. Docker assigned target image IDs that differ from the local archive config digests; the example uses the verified target references. Recheck after any later import. Do not substitute an unrelated application image or build on the constrained VPS without capacity review.

Mark each as Runtime and Literal, with Buildtime disabled. The native database encrypts their values. Compose passes the four keys only to the backend; the fixed `/etc/pocketstats/pocketstats-compose.env` is no longer an active source. Keep that former protected file only for rollback until the new native delivery has been accepted. Do not put real values in Git, build inputs, resolved configuration output or this document.

The current private shared-dashboard guard still requires Atlas database `test`, a matching URI and the existing protected version-2 marker. Other datasets require a separately reconciled guard/marker decision. Changing an editable value does not bypass application validation.

`VUE_APP_BACKEND_URL` is a public runtime setting passed only to the dashboard. Empty means the browser's current origin and retains the exact private `/stats/...` proxy routes. A nonempty setting must be an HTTP(S) or root-relative API base without a query, fragment, quote, backslash or newline; a trailing slash is normalized. It is not a secret. `dashboard-start` validates it and checks the pinned public index/app hashes before generating browser configuration plus an adapted index/app bundle under bounded `/tmp` tmpfs. No frontend rebuild or extra writable host mount is needed. The original public release stays unchanged. Backend secrets are never included in the generated browser configuration.

Set the native Custom Build Command to `true`: these are already-loaded runtime images, with no build sections, and required backend variables are runtime-only. Keep Custom Start Command empty to use the native Raw Compose path. Leave both image-selection variables at the verified target IDs and `pull_policy: never`. The build step must not parse required runtime keys or receive their values. Coolify generates runtime env after this no-op step. ## Loopback publication and host firewall prerequisite

On Docker29.8.1, a bounded synthetic Nginx fixture was healthy inside an internal-only bridge but had no effective published port and refused host loopback HTTP. The same fixture on a noninternal bridge published the requested loopback port and returned200. Both disposable networks/containers were removed. Internal network membership alone does not establish host published-port reachability.

The proxy now joins a separate `proxy_ingress` bridge with stable host interface `ps-ui-ingress`, in addition to the existing internal dashboard network. Backend network membership and its unpublished port remain unchanged. Proxy publication remains exactly `127.0.0.1:18081:8080`; it joins no shared Coolify or Atlas-egress network.

Do not activate this revision until Ansible-owned host INPUT and FORWARD rules deny NEW connections originating from `ps-ui-ingress`, including IPv4/IPv6, while admitting established replies and the intended host-originated loopback connection. A noninternal bridge supplies a gateway; Compose alone does not block its outbound traffic. Host firewall syntax, ordering relative to Docker rules, persistence and actual allowed/denied behavior must be verified before deployment. This PR supplies only the application-side network definition, not the required host rules or a claim of runtime acceptance. The fixed bridge name permits only one active instance on this host; preview deployments must remain disabled.
